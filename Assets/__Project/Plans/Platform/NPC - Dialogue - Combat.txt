  How It Works

  The solution follows this flow:

  1. When an Ink story is loaded via LoadStory(), the binder's BindAllExternalFunctions() is called
  2. The binder registers trigger_combat(int) with the story manager
  3. When Ink calls ~ trigger_combat(1), the C# handler executes:
    - Stores enemy count (for future use)
    - Logs the function call
    - Fires DialoguePresenter.OnCombatTriggered event
  4. DialogueActiveState handles the event and sets _combatTriggered = true
  5. Later, when Ink tag # outcome: Combat is processed, the dialogue ends and combat transition occurs

Fix Dialogue UI Not Showing

 Problem

 The dialogue UI doesn't appear when the character enters a platform with dialogue content. The DialogueActiveState properly transitions and calls DialoguePresenter.StartNpcDialogue(), but the UI remains hidden.

 Root Cause

 The DialoguePresenter has a _view field (IDialogueView) that remains null. When StartNpcDialogue() calls _view?.Show(), nothing happens due to the null-coalescing operator.

 Why is _view null?
 - DialoguePresenter constructor doesn't accept IDialogueView as a parameter
 - NarrativeInstaller binds DialoguePresenter and IDialogueView independently
 - SetView() method exists but is never called anywhere in the codebase
 - The two components are never connected

 Solution: Constructor Injection

 Add IDialogueView to DialoguePresenter's constructor so Zenject automatically injects and connects it.

 Why this approach:
 - Follows CLAUDE.md rules: "Prefer constructor injection for pure C# classes"
 - No breaking changes (all instantiation is via Zenject, no manual new DialoguePresenter() calls)
 - Clean dependency injection pattern
 - Fail-fast if view is missing (catches configuration errors at startup)
 - Consistent with other presenters in the codebase

 Implementation Steps

 1. Modify DialoguePresenter Constructor

 File: Assets/__Project/Scripts/Narrative/Dialogue/DialoguePresenter.cs (lines 50-59)

 Add IDialogueView parameter and initialize view immediately:

 public DialoguePresenter(
     IStoryManager storyManager,
     INpcDataProvider npcDataProvider,
     IDialogueView view)  // ADD THIS
 {
     _storyManager = storyManager ?? throw new ArgumentNullException(nameof(storyManager));
     _npcDataProvider = npcDataProvider;
     _view = view ?? throw new ArgumentNullException(nameof(view));  // CHANGE THIS
     _model = new DialogueModel();

     SubscribeToStoryEvents();
     SubscribeToViewEvents();  // ADD THIS - subscribe immediately
 }

 2. Update NarrativeInstaller Binding Order

 File: Assets/__Project/Scripts/Core/DI/NarrativeInstaller.cs (lines 102-129)

 Reorder bindings so view exists before presenter is created, and add validation:

 private void InstallDialogueSystem()
 {
     // Dialogue view binding (MUST be first so presenter can use it)
     if (_dialogueView != null)
     {
         Container.Bind<IDialogueView>()
             .FromInstance(_dialogueView)
             .AsSingle();
     }
     else if (_dialogueViewPrefab != null)
     {
         Container.Bind<IDialogueView>()
             .To<DialogueView>()
             .FromComponentInNewPrefab(_dialogueViewPrefab)
             .AsSingle()
             .NonLazy();
     }
     else
     {
         throw new System.InvalidOperationException(
             "[NarrativeInstaller] No dialogue view assigned! " +
             "Assign either _dialogueView or _dialogueViewPrefab in the inspector. " +
             "DialoguePresenter requires a view to function.");
     }

     // Dialogue presenter - will automatically receive IDialogueView via constructor injection
     Container.Bind<DialoguePresenter>()
         .AsSingle();
 }
