Track B — Sites & Landscape реализован полностью и закоммичен в четыре фазовых коммита (8e49606 → 8577d22 → db7a587 → 735a06c, ветка dev). Контентная половина брифа («что и где наполняется») готова; визуальная половина («читается как одно место») — отдельный M5-пункт, для которого теперь есть шов данных.

Что теперь происходит в игре:
- Квест может притянуть поселение: при выпадении квестового слота идёт взвешенный ролл — ~40% квест остаётся «диким» (одинокий странник), иначе резервируется Village (2–3 платформы) или City (4–5) непрерывным блоком; история может жёстко потребовать сайт тегом site:<id>. Camp/Ruin/Lair приходят по редкому амбиентному роллу (1-к-14 c жёстким интервалом 6), канал триггера выводится из якорного бита сайта — без спец-кода.
- Блок наполняется рецептом: якорь первым, затем взвешенный fill (город: townsfolk 5 / market 3 / guard 2 при бюджете 2–3), остаток — связующая пустота. Городские NPC-слоты играют две новые «болтливые» истории (TownsfolkGossip/Grumbler — ink + json + SO авторизованы, интент выводится как Plain), и они никогда не занимают квестовый слот. Combat-биты тянут врага по флейвор-тегу из пула (bandit/guard/den-monster затегированы), лут-биты (market/stash/chest/relic) смещают веса таблицы биома через существующий механизм BiasTags.
- Детерминизм и обратная совместимость доказаны тестами: пустой каталог сайтов = бит-в-бит поведение до изменения (регрессионный passthrough-тест), все 16 старых тестов планировщика прошли без правок поверх нового аллокатора. Итог по сьютам: 39/39 (домен+аллокатор+пулы+acceptance) и 20/20 (планировщик) во внешнем прогоне, полная компиляция игры и тестов чистая. Acceptance-гистограмма на 600 слотов подтверждает критерии брифа: >60% Wild, редкие непрерывные блоки, город «люднее» деревни, у руин/логова нет горожан, одинаковый сид → одинаковый мир.
- Расширяемость — данными: новый сайт = один SO-ассет (family-default + явные override-тумблеры, так что новые атрибуты не ломают существующие ассеты); новый флейвор = строка в рецепте + тег на враге/луте/истории. Рецепты «Add a site / combat flavor / loot flavor / townsfolk story» — в новом системном доке Docs/world-sites.md.

Документация синхронизирована: world-sites.md (новый док, добавлен в README), CHANGELOG — по записи на фазу, ROADMAP — пункт Sites & landscape закрыт, заведены follow-ups (отложенные поля паспорта/тира/биома, quest-bearer-как-fill, отдельные лут-таблицы по флейворам, настоящие враги по флейворам; пункт о save-state теперь покрывает и очередь сайт-блока).
