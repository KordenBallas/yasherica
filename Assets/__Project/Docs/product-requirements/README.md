# Product Requirements — Verified Briefs

This folder holds **product-owner requirement briefs**: feature specs written at a
product-owner level (user stories, what the feature does, how it should feel, acceptance
criteria, content/authoring rules, out-of-scope) **after** they have been discussed and
**verified** with the product owner. Each brief is the source of *intent* handed to the code
track for implementation.

## What these are (and aren't)

- These describe **intended** behavior, before it is built. They are the **exception** to the
  rest of `Assets/__Project/Docs/`, which documents systems **as implemented**.
- They are **not** the `/design` tree. `/design` holds forward-looking *design intent* (world,
  lore, narrative, crafting). A product-requirements brief is the concrete, verified hand-off
  for one change — the "what to build now", not the long-term design vision.
- They are **product-owner level, not technical**: no architecture, class names, or
  implementation steps. The code track derives the technical "how".

## Lifecycle

1. The product owner and Claude discuss a need and verify the requirement.
2. The agreed requirement is committed here as one brief (English, product-owner level).
3. The code track implements it; the **as-implemented** behavior is then documented in the
   relevant system doc per `Assets/__Project/CLAUDE.md §8`.
4. The brief stays as the original record of intent — it is not rewritten to match the code.

| [Crafting & Mutation — Socketed Blanks](crafting-mutation-socketed-blanks.md) | Replace "feed the cauldron and hope" with **building the organ**. Puzzle = readable direction + hidden menu + slot interaction (anti-recipe-table). Scarce **Blank Rack** = multi-track tension; traits hidden (archetype color + tier glow; cauldron-voice hints). **Retires the shipped feeding/digestion flow.** Card visuals + biome bias are separate briefs |

Facing is **free/unlimited** to change (chess-like); ring abilities unaffected; aim = **turn the hero** (reuse the direction input). Enemies carry a **committed facing** in their locked intent → reading facing = reading where the blow lands. Per-ability aiming intentionally dropped; multi-directional "turn-as-a-queued-step" deferred |
| [Combat — Enemy Intent Phase](combat-turn-intent-phase.md) | Turn structure prerequisite for the ghost telegraph. Resolution order **player then enemies**; determinism preserved. AI scoring unchanged — only decide-timing + commitment change. Intent *visuals* live in the ghost-telegraph brief; initiative order + smarter AI deferred |
| [Combat — Ability Ghost Telegraph](combat-ability-ghost-telegraph.md) | Turn the "where" cell-highlight into a **"what it does"** preview. Each unit — **player and enemy** — shows its **queued abilities as icons above it**; **hovering an icon replays that ability's ghost**, including enemy icons → **read enemy intent**. One mechanism unifying queue display + battlefield telegraph + enemy-intent. Queue-simulation preview + the enemy turn-flow that surfaces the plan are flagged dependencies |
| [Quest-Offer Card](quest-offer-card.md) | The quest **offer** as a rare-prize card (now that artifact tier ships). Reward-roll, competing-offer logic, and card art are separate |
| [Mutation Choice Cards](mutation-choice-cards.md) | The **unseal variant menu** of Socketed Blanks, as a hand of cards. **Front visual-first**: body part pictured centre + ability icons beneath (no stat blocks). **Flip** (corner button) → the replaced part + its abilities (before→after on demand). **Hover an ability icon** → description tooltip; **hover the part** → mini-model popover of the hero wearing the new part. | [Biome Visual Styles](biome-visual-styles.md) | Data-driven per-biome look: one appearance config per `LevelTheme` (Forest/Desert/Mountain/Cave, mirroring the biome-loot SO) = ground material, **palette key** (a muted key modulation of the master palette, inherits the render-look bible), light, and a **feature pool**. | [Run Escalation](run-escalation.md) | Make a run **feel like it climbs** — the first **consumer** of the `run_escalation_tier` fact (published by biome-selection). **One mechanism, three effects:** every placeable content (story, monster) carries a **run-tier band** and the director filters the eligible pool by the current tier. **(1) Register** — stories band into **Backwater → Courts → Divine/Apex**; low-register content ages out as high-register enters ("epic, but vile"). **(2) Difficulty** — monsters carry the same band; a higher tier draws a **tougher pool** (bigger bodies / more parts / nastier kits from the same part system), **NOT a stat multiplier** — difficulty is *different creatures to read* (Pillar 4), never inflated HP. **(3) Density does NOT scale with tier** — the breathing world holds at every altitude; the local "a court is busier" read is owned by **Site-tier**, not run-tier. `min`-tier opens content upward, `max`-tier optional. Deterministic + data-authored (unbanded = eligible everywhere). Run apex/finale, the register content itself, per-tier stat scaling, and any tier UI are separate/deferred |
| [Biome Selection Along the Run](biome-selection-along-the-run.md) | Stop the run being stuck in hardcoded **Forest**. The biome **advances along the run** through an **authored, seeded, escalating** sequence: each biome has an **escalation tier** (backwater → approach-to-the-Order), the run **climbs tiers**, and within a tier the biome is **seeded-picked from a weighted pool** → runs **diverge** in which homelands they open (D18). Travel in **stretches** (not per-platform flicker); a biome switch swaps its **monsters, loot, look**, and — for a homeland — its **race**. **Cave stays out of rotation** (no race yet). Deterministic + data-authored (new/re-tiered biome = no code); the **current tier is published as a fact**. Difficulty/tone escalation (D19), the run apex, and a player-choice map are separate/deferred |
| [Body-Part Authoring](part-authoring.md) | The **authoring contract** for a body part so a designer **or AI** can produce a valid one alone: **slot**, **size/proportion budget**, **socket & sub-part conventions** (ears/eyes on a head's sockets), **skeleton family** (+ marking a part that **pulls its own skeleton**, per the independent body-plans model), and **rarity re-texture of one mesh** (common frog head green vs legendary set). Conform to the published bind-pose/bone-naming contract. Authoring rules only — the runtime skeleton-swap mechanics, the race roster, and the generation pipeline are separate (see `design/characters/model.md`, `needs-code.md`) |
| [Director — Threads, Continuity & Fact Horizon](director-threads-and-continuity.md) | The **P2-3** long pole (after the shipped actor/faction eligibility): make a run read as **one growing saga** and place its beats **in causal order**. A **thread** becomes a first-class managed entity (id + state), in two kinds — **ephemeral** (can **expire** silently past an authored lifespan → failed/expired indicator, no closing beat) and **arc** (long, expiry-exempt). Either kind **fails on fact-conflict** when the player makes its premise impossible (joined the Lizards → the "join the Foxes" thread fails; killed the king → the "befriend the king" arc fails) — the mutual-exclusion mechanism, again just a state change + indicator (**no closure-beat content**). A small **concurrency ceiling**; the director **advances** live threads over opening new ones. **Cross-window continuity**: a consequence beat is **held until its cause's fact is live** and never placed early; an already-offered/resolved/failed story is **never re-placed** (correctness over density). Also draws the **run-scoped vs meta-scoped fact boundary** now so save/load (P2-2) persists a clean partition. Deterministic. Spine lane (P3-1), escalation (P3-2), the cross-run meta store + file IO + consumers (P2-2/P3-3), and a player-facing saga view (near P1-11) are separate |
| [Independent Body-Plans & Skeleton-Swap Runtime](body-plan-skeleton-swap.md) | ✅ **Shipped 2026-07-04** (`character-system.md` R19–R24; see CHANGELOG). The **runtime** half of independent body-plans (**P2-1**, supersedes `character-system.md` R10/R3). Most parts ride one **base frame** and swap cheaply as today; a rare **skeleton-changing part** **pulls its own body plan** (a legless serpent, a quadruped) and the body **re-forms** around it — the honest, felt cost of reshaping your frame. Which frame governs is decided by authored **priority**, **deterministically**; parts with **no attach point** on the new frame are **shed**. UX: **confirm-before-change** showing which parts come off (decline = no change), and **shed parts return to inventory** (not destroyed). First scope = the full machinery + base frame + **two** demonstrator plans, authored by the **code track as placeholder test frames**: a **legless serpent** (removes attach points → sheds both legs) and a **spider-legged** frame (adds attach points → sheds the base legs), together testing both directions and making the priority rule falsifiable (serpent+spider equipped → higher priority governs). The three starting races are all base-frame (need no special skeletons); passport reads a smaller frame as simply fewer markers (no special rule). Production frame meshes (P5-6), further plans, rarity re-texture, and the generation pipeline are separate |
